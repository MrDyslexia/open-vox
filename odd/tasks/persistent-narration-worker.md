# Persistent narration worker

## Objective

Reuse a Python worker and loaded LID/Kokoro models across narration requests, reducing repeated initialization while preserving isolation between sessions and independently opened OpenCode instances.

## Context and chosen architecture

The CPU/GPU benchmark completed 266 valid jobs. The current per-utterance GPU path repeats approximately 2.65 seconds of preparation plus model loading. Warm processing is substantially faster, but the benchmark's in-process loop does not prove production transport performance.

Use one private, lazily started worker slot per memoized Kokoro engine/plugin instance. Sessions within that instance serialize requests through the existing queue; other plugin instances own independent pipes, workers and caches. Do not introduce a global daemon, port, shared registry or cross-instance model service. Each instance consumes separate model RAM/VRAM. This isolates cancellation and ownership, not aggregate hardware contention.

## Scope and constraints

- Versioned bounded UTF-8 private-pipe request/response protocol; instance/generation/request identity validation, per-request process handles, no automatic inference replay on faults.
- Retain models/tokenizers only. Never retain conversation plans, synthesized outputs or text as a cross-request cache. Keep existing audio-cache ownership and Repeat-without-inference behavior.
- One active request per worker, preserving existing bounded queue policy. Cancelling queued work must not kill another session's active synthesis. Active cancellation may terminate only that instance's worker; the next admitted request reloads on demand.
- Wait for actual child exit before releasing cancelled output-file holds. Malformed, oversized, foreign or duplicate replies fail closed, settle owned requests and retire the worker.
- Release workers on Off/disposal and after a bounded idle timeout. Replace on runtime/model identity changes. Keep voice/speed/tone as request settings when model assets remain identical.
- Full GPU qualification remains mandatory per worker generation; lightweight stamp checks invalidate changed markers/assets. Do not weaken provenance checks or mix CPU/GPU environment tuples.
- Preserve the one-shot Python helper, GPU UTF-8 flags, Pause/Resume, playback-rate controls, device diagnostics, manual Speak recovery, session scoping, cache promotion and failure fallback.
- Fix the existing active-session deletion path narrowly if it globally drops other sessions' queued jobs. Do not expand unrelated behavior.
- No installs, downloads, driver/global Python/config changes, OpenCode TUI changes, remote operations, commits or pushes. Preserve all existing uncommitted GPU/benchmark work after 2e1f29c and existing caches.
- Verification may use synthetic local CPU/GPU inference and temporary WAVs under the approved Temp/opencode root, with no audio playback. Runtime/profile settings are injected; the user's active configuration remains unchanged.
